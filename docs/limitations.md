# 信任边界与限制

- 需要本地编排/执行支持。插件 hooks 要由用户审阅并信任；不自动写信任记录，不替用户绕过安全界面。支持矩阵以 [Codex Hooks](https://learn.chatgpt.com/docs/hooks) 和 [插件文档](https://developers.openai.com/plugins/build/plugins) 为准。
- 自动执行仅对显式启用 `agent_hooks` 的仓库生效。策略命令拥有用户本地运行权限；执行器不是隔离沙箱，不应用于未经审阅的不可信仓库。
- Hook 不是完整安全边界。部分工具路径可能不触发，用户也能绕过本地 Git hooks；正式合并、分支规则、审批与部署控制依赖服务端。
- 不把测试配置、JUnit 或 JSON 当作防篡改证明。用例是否验证正确业务结果、策略是否被削弱仍需评审；CI 应使用可信策略与运行环境。
- 当前导出快照不支持 symlink、submodule 和 Git LFS 内容展开，也不包含历史、未跟踪文件或原工作区依赖。symlink/submodule 和未展开 LFS 指针明确拒绝；这些项目应使用项目专属快照方案。
- 代码指纹不覆盖全部忽略文件、任意外部服务、环境变量或动态数据。锁定依赖并记录部署环境/产物，外部输入改变时重跑。
- 检查串行执行，遇到首个失败停止。不提供自动重试掩盖失败、测试隔离白名单、自动生成覆盖率阈值或自动批准。
- 同一仓库并发运行通过锁拒绝。异常终止留下锁时，确认原进程已结束后才能移除 `.testing-results/run.lock`。超时会尝试结束子进程树；无法控制刻意脱离进程树的程序。
- 代理编辑事件无变更时跳过；结束 hook 最多请求一次修复。遇到错误或继续失败会允许如实交付阻塞状态，不把代理无限留在循环里。
- 默认包提供通用检查协议与阶段，不附带业务系统的真实压测、故障注入、生产请求或人工 UAT 实现。这些能力由经授权的项目命令接入。
- `scripts/package_plugin.py` 做本地结构、路径与引用核对；不等于已通过官方公共目录审核，也不等于已在桌面端逐个验证真实生命周期事件。
