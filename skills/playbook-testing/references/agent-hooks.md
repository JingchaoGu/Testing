# AI 编码代理 hook

## 接入前

识别用户指定的代理及运行形态、项目配置和平台版本。查询当前官方文档或可用本地说明，确认事件、输入、输出、失败及超时语义。此文用 Claude Code 举例，不暗示其他代理支持相同 API。

若没有可用的生命周期 hook，复用项目任务命令、测试 watcher 和 Git/CI 门禁，说明代理端只是流程约定；不要发明配置键，也不要把通知接口当成阻断接口。

## 事件到阶段

| 事件职责 | 动作 | 通过与失败语义 |
| --- | --- | --- |
| 会话/任务开始 | 读取命令映射、范围和基线；必要时注入简短上下文 | 不每次启动全量测试，不把事件存在当作具备阻断能力 |
| 工具调用前 | 对提交/推送等受控动作核对当前阶段条件 | 仅平台支持时拒绝调用；正式保障仍依赖 Git 和 CI |
| 一批写入后 | 合并变更事件，执行 edit 的相关快速检查 | 允许暂时失败，向代理提供定位信息 |
| 任务准备结束 | 对当前变更执行 task-finish 检查，核对适用证据 | 未完成则继续修复或清楚结束为未验证；防递归 |
| 会话结束 | 保存已生成的摘要或运行标识 | 不在退出后尝试阻止已完成的操作 |

Claude Code 的常见映射：`PostToolUse` 对应执行后反馈，`PreToolUse` 对应调用前控制，`Stop` 对应响应结束前反馈。`PostToolUse` 不能撤销已发生的操作；异步 hook 不能用来直接阻断；`Stop` 不等于整个工程任务已经完成，应按是否存在本任务代码变更判断适用性。详见[官方 reference](https://code.claude.com/docs/en/hooks)与[接入指南](https://code.claude.com/docs/en/hooks-guide)。这些接口会演进，实际配置时重新核对。

## 执行与反馈

1. 读取可信结构化事件，提取工作目录、工具类型和受影响路径。路径先验证为目标工作区内的实际路径；通过参数数组或正确引用传递，不把事件字符串拼为 shell 代码。
2. 用真实文件变更或工作区快照选择检查，不只匹配 `Edit|Write`；shell、MCP 或其他工具也可能写文件。最终检查重新读取差异，不能只信事件账本。
3. 合并短时间重复写入，限制同一工作区/套件的并发；新快照到来后丢弃旧结果的放行资格。测试输出、报告或格式化写入不应无限触发自己。
4. 返回简短定位：阶段、被测版本、命令、失败用例/错误、报告路径，以及是否需要继续处理。详细日志落到项目已有的报告目录。
5. 原样保留底层测试结果，并单独映射平台的退出码/JSON。例如不能假设命令的 exit 1 在所有代理上都意味着阻断。
6. 结束检查只覆盖本次任务适用阶段；用户提问、阶段性讨论或明确停止请求不应触发编码修复循环。

## Red、重试与无法修复的失败

- edit 处于 TDD Red 时反馈失败，允许代理继续写实现；只有明确完成点才要求适用检查最终通过。
- 同一失败的自动修复应有小的可配置预算；未收敛时报告失败和已尝试措施，不反复要求代理继续。
- 结束事件重复触发时结合平台的防循环字段和本地运行记录。Claude Code 的 `stop_hook_active` 可用于识别因结束反馈而继续的调用；提前退出不能把未通过的测试记为通过。
- 基线已失败、环境不可用或权限缺失时保留未验证状态，不删检查、不伪造成功，也不自动申请发布或生产权限。

## 验证

在隔离样例仓库验证：写入后触发一次相关检查；修改后旧证据失效；新失败能进入代理上下文；用户讨论和无变更响应不重复测试；结束检查不会无限循环。若代理环境不可用，说明仅完成配置静态检查，不宣称已验证实际事件。
