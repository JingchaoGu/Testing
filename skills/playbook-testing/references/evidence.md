# 测试证据与放行契约

本契约是技能的工程建议，按项目已有报告格式映射；不要求为简单仓库新增数据库或完整证据服务。

## 最小证据

| 字段 | 含义 |
| --- | --- |
| stage、check_id、run_id | 哪个阶段、哪项检查、哪次执行 |
| snapshot | commit/tree 标识或完整工作区输入指纹，含适用未跟踪源码；不是只记录 HEAD |
| comparison_base | 增量选择的基线，适用时记录 |
| command、cwd | 实际命令参数与工作目录，凭据脱敏 |
| inputs | 影响结果的锁文件、配置和工具链版本/指纹 |
| environment、artifact | 适用环境标识、部署产物 digest；禁止记录秘密明文 |
| started_at、finished_at | 执行时间与超时判断依据 |
| status、exit_code | 归一状态与底层进程结果 |
| counts、report | 测试执行数、失败/跳过数及可定位的原始报告 |
| reason、approval | 未运行/不适用/豁免原因与项目要求的批准证据 |

没有唯一工作区指纹机制时，重新检查快照或重跑，不能拿 HEAD 相同推断代码未变。仅缓存可证明相同输入的结果；正式 CI 的信任来源与权限另行保证。

## 状态语义

| 状态 | 含义 | 必需门禁 |
| --- | --- | --- |
| passed | 命令成功，报告和实际验证均符合策略 | 输入仍相同且来源可信时可通过 |
| failed | 断言、构建、扫描或其他质量规则失败 | 不通过 |
| error | 环境、工具、报告解析或执行器异常 | 不通过，不能说应用一定存在缺陷 |
| timed_out / cancelled | 未取得完整结果 | 不通过 |
| not_run / pending | 尚未执行或未完成 | 不通过 |
| skipped | 检查或整个套件被跳过 | 必需项不自动通过 |
| not_applicable | 确实不适用，有理由并完成项目规定的确认 | 作为策略中明确的例外，不伪装成测试通过 |

开发反馈阶段可以继续写代码；状态本身不因此变为 passed。已有失败单独标识，不自行忽略。人工豁免若被项目允许，应记录对象、原因、批准者与有效范围，保留原始失败结果。

## 正式门禁的判定顺序

1. 从当前阶段的可信策略列出应执行检查及适用条件。
2. 核对每项都有对应证据，且属于正确候选、配置、环境和产物。
3. 核对进程、报告及检查级状态；缺失、解析失败或冲突不能通过。
4. 对测试套件核对实际执行数量及项目约定的覆盖/选择范围。收集到零项、全部跳过或关键用例未运行不通过；非测试型命令不要求用例数。
5. 按项目策略处理部分跳过、覆盖率、性能阈值和明确例外；不生成全局百分比。
6. 等待所有必需自动化与人工条件；保存本次判定，说明阻塞项。

覆盖率只是证据之一；测试文件数量、名称、模型声称“测过”以及单纯 exit 0 都不能独立证明充分验证。

## 需要防止的错误结果

- 文件改变后仍使用旧报告；只比较 HEAD 而漏掉 index/工作区差异。
- 错误地将运行器返回成功、零测试或全跳过当作测试通过。
- 汇总遗漏 cancelled、未触发或缺报告的必需作业。
- 重试直到偶然成功却丢弃初次失败；跨环境直接比较性能而忽略配置变化。
- 编辑 hook 已异步启动就把发布门禁标绿。
- 让代理通过削弱策略、自评批准或改变预期来消除失败。
